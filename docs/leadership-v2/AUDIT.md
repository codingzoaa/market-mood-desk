# Phase 1 — 코드·데이터 가용성 감사

감사 기준: `7fc48434380e47f115ee82b5fb4edb4e250b808d` (2026-10-20 KST).
대상 저장소: codingzoaa/market-mood-desk. 이 보고서는 소스 코드·스키마·로컬 검사를 근거로 한다. 이번 작업에서는 운영 D1의 행 수·현재 데이터 내용·LS 공급자 API 가용성/정책을 조회하지 않았다. 현재 운영 데이터에 과거 자료가 충분하다고 주장하지 않는다.

## 1. 호출 구조와 보존 범위

- `worker/index.mjs` → Cron → `collect()` → D1 lease → 동일 TLS 세션의 OAuth 및 허용 TR → 날짜별 `snapshots` UPSERT. 시장별 거래대금 최대100개, 최대5페이지. 종목 거래대금은 LS 백만원을 원으로 변환한다. 테마는 상승률 ≥4%이며 미분류인 상위12개를 회차별 보강한다.
- 수집 평일 09:00–15:30분, UTC Cron 2개. OAuth·LS TR·네이버 호출 모두 시간 제한을 적용한다. 시간이 지났다고 FINAL이라는 필드를 만들지는 않는다. 거래일 확인은 삼성전자 최근 일봉과 세션 개장 시각에 의존한다. 전 종목 거래정지·특별장·공식 거래일 캘린더 확인을 대신하지 않는다.
- `worker/details.mjs` → 별도 lease → KOSPI/KOSDAQ 지수, 시장별 상승/보합/하락 수, 당일5분 지수차트, 현물/파생 수급; 네이버 업종 구성과 시장 종목의 업종·등락률·시가총액 보강. `state`의 `details:DATE`를 덮어쓴다. 각 하위 `asOf`를 보존하지만 이는 수집 시작 시각이며 공식 종가 확정 증거가 아니다. 상세 실패는 기존 정상 부분을 유지한다.
- `worker/schema.sql`: snapshots(date PK), state(id PK), themes(symbol PK)뿐이다. 날짜별 최신 값만 남고 5분 관측 이력/점수 이력 테이블은 없다. 최대365일 보관 조건은 365거래일 이력이 있다는 뜻이 아니다.
- 공개 GET → 저장 D1 조회만. 읽기가 공급자 API를 실행하지 않는다. `/api/dashboard`는 요청일을 끝으로 **28달력일**만 응답한다. 장기 계산 기준이 되는 20·60거래일 공급 경로는 없다.
- `src/live.ts` → 출처/날짜/필드 검증 → 브라우저 캐시; `src/storage.ts`는 개인 메모·관심종목과 파일 저장을 담당한다. 장중 이력/확정 플래그가 전달되지 않는다.
- `src/desk.tsx`: 기존 국장/주도 섹터/거래대금/주도주 캘린더 유지. 국장에는 카드와 상관관계만 남아 있다. 이번 PR은 UI 진입점에 새 모듈을 연결하지 않는다.

## 2. 기존 분석 함수의 정확한 의미

| 함수 | 실제 역할 | 새 엔진에서의 취급 |
|---|---|---|
| eligibleStocks / turnoverLeaders | ETF 목록·유형·상품명 제외 후 표본 내 대금 상위N 선정 | 상품 제외 재사용. 유형 마스터 누락은 감사 한계 |
| gainers | 제외·시장 필터 → 대금 상위N → 당일 ≥4% | 후보 필터 유지. 전체 Breadth로 사용 금지 |
| rankSectors | 전달받은 종목의 복수 테마에 대금을 균등 배분, 대금 가중 등락률·점유율 | 기존 경로는 gainers 결과여서 강세 표본 집계. 고정 업종 수익률/전체 확산도 아님 |
| rotations | 최근28달력일, gainers + rankSectors의 대금 비중 이력 | RS5/20 로테이션과 다름. 별도 모듈 추가 |
| riskScore | breadth/VIX/credit/SOX/금리의 외부 입력 위험점수 가중합 | 주도 점수와 무관. LS 수집기는 필요한 riskFactors를 채우지 않음 |
| regime | 위험점수 50/75 임계값 분류, 없으면 판단 대기 | 새 주도 등급으로 대체하지 않음 |
| closingPoints | 지수/개인수급 모두15:30분인 날짜만 상관관계에 포함 | 시간 필터일 뿐 공식 FINAL 인증이 아님. EOD 엔진에 재사용 금지 |

ETF 제외는 현재 이름 규칙과 수집된 KODEX 목록에 의존하는 구간이 있다. 신규 브랜드·종목명이 예상과 다를 때 완전한 상품 구분을 보증하지 못한다. 향후 승인된 종목유형 마스터를 필수 입력으로 삼아야 한다.

## 3. 데이터 가용성 표

| 정보 | 현 코드에서의 관측/저장 | V2 활용 가능 여부 |
|---|---|---|
| 코드/이름/시장/현재가/등락률/누적대금 | 시장별 최대100개 | `SAMPLED_UNIVERSE`. 거래대금 상위 진출입 편향 존재 |
| 종목 전일종가 | 없음 | 등락률 역산으로 공식 값 생성하지 않음 |
| 종목 OHLC/20·60일 수정주가 | 없음 (005930 일봉2개는 거래일 검증용) | 구조/기간RS 불가 |
| 동일5분 슬롯 20거래일 누적대금 | 없음, 날짜별 UPSERT | 장중 RVOL 불가. 전일 최종대금 대체 금지 |
| 종목 테마 | ≥4% 미분류 일부에 순차 보강, 24h TTL | 고정된 전체 업종 구성으로 취급 금지 |
| 네이버 업종·등락률·시총 | 상세 히트맵 별도 저장, 페이지 종료/중복 검증 | 구성 후보 조사에는 활용 가능. 전일 고정 구성·기업행동·가격/대금 이력 없음 |
| 지수 현재값·등락률·상승/보합/하락 | 상세 응답에 있음 | 원천 시장 Breadth는 관측 가능. 종목 표본 비율과 혼합 금지 |
| 지수 가격 이력 | 당일5분봉만 | 5·20일 벤치마크 이력 불충분 |
| 정상거래일 캘린더·수정주가·상장폐지 정보 | 없음 | 공식 제공원 추가 검증 필요 |
| 공식 마감 확정 플래그/최종 거래대금 증명 | 없음 | 시간만 보고 EOD FINAL 부여 금지 |
| 과거 점수·주도주 출현·점수 기준일 구성 | 없음 | 누적 수집/저장 체계 승인 이후 확보 |

## 4. 구현한 품질 모델

`src/analytics/quality.ts`의 `legacyDataQuality()`는 기존 스냅샷에 `SAMPLED_UNIVERSE`와 누락 필드 목록을 부여한다. stockCount/classifiedCount는 상품 제외 후 표본 기준이다. 기존 저장 스키마에는 확정 이력 증거가 없으므로 historicalTradingDays=0이다. 10분을 초과한 관측은 stale이다. 이 값은 ‘현재 진행 중인 수집이 실패했다’는 의미가 아니라 관측 연령이며, 마감 다음 날에도 과거 관측이 오래됐음을 나타낸다. 마지막 성공 시각은 cutoff 이후 값을 반영하지 않는다. UI 표시는 Phase 3에 남긴다.

## 5. 확장 제안 — 승인 전 실행 금지

1. 문서로 확인한 LS 종목 마스터·수정 OHLC/벤치마크·공식 거래일 및 확정 상태 제공원 조사. 이번 PR에서는 TR 추가·실호출·공급자 호출량 변경 없음.
2. 표본을 유지하면 표본 내 고정 구성으로 명시. 전체 시장을 선택하려면 전체 종목·거래정지/상장폐지/기업행동 및 구성 버전을 함께 확보해야 함.
3. 5분 원본 관측은 append-only, 동일 거래일/슬롯/종목/원천 버전 키. 동일 시각 평균은 과거 실제20거래일이 모두 쌓인 뒤 계산. 중간 누락이면 null.
4. 종가 확정 데이터는 관측과 분리. 15:30이후 호출이 필요하다면 현 수집 종료 정책과 충돌하므로 **별도 승인**. 승인 전에는 공급자가 확정임을 증명하지 못하는 날짜의 FINAL 계산을 막는다.
5. 원본 확보 후 엔진을 분리된 서버 배치로 연결하고 결과/품질/버전을 저장. 조회 API는 계산·LS 호출을 하지 않는다. 테이블 설계와 용량 산정은 PLAN.md 참고.
6. 과거 백필은 종목 범위·기간·호출량·기업행동 처리·운영 부하 계획을 별도 승인받은 뒤 실행. 백테스트는 지금 실행할 수 없음.

Phase 1 판정: 코드 감사와 품질 모델 구현 완료. 운영 데이터가 점수 요건을 충족한다는 판정은 아님. 공식 종가·동일시각 RVOL·가격 이력 확보는 미해결이다.
