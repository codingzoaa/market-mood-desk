# LS 손실 감지기

첨부 KiwoomLossGuard 0.7.0 README의 공개 동작 설명을 참고해 LS용으로 새로 구현했다. 원본 exe를 패치하거나 원본 음성·이미지를 재배포하지 않는다.

## 웹

기존 본인 전용 계좌분석 Worker의 손실 감지기 패널. Access 인증을 통과한 소유자만 설정·상태·조회 API에 접근한다. 기존 암호화 D1 account_state에 일별 최초 기준·설정·최근 90일 집계 기록을 저장한다. 계좌 데이터는 localStorage/IndexedDB에 저장하지 않는다. 감시 시작을 누른 동안 30초 간격으로 조회하며 페이지 숨김·절전·종료 시 중단된다. 백그라운드 감시는 Windows판을 사용한다.

- LS t0424OutBlock.sunamt: 최초 관측 순자산, dtsunik: 실현손익, tdtsunik: 평가손익. OutBlock1.dtsunik은 종목 평가손익이므로 사용하지 않는다.
- 기본 손실 한도 최초 관측 순자산 3%, 사전 경고80%, 한도 반복5분. 고정 원화 금액 및 실현+평가 변화 모드 선택 가능.
- 평가 변화 모드: 당일 실현손익 + 현재 평가손익 − 최초 평가손익. 계좌 전체 수익률이나 현금 입출금 조정 수익률이 아니다.
- 오후 기준 기본11:00. 늦게 시작하거나 조회 지연 시 실제 관측 시각과 추정 표시. 오후 손익/수익 반납은 실현손익 차이 기준.
- CSPAQ13700 당일 주문 조회: 부분 체결과 정정은 원주문 체인 기준 1회. 원주문 누락·연속조회 미완료·필드 오류이면 횟수는 확인 불가. 주문 전송 TR은 없다.
- 3회 연속 조회 실패 경고. 누락을0으로 보정하지 않으며 마지막 정상 시각을 표시한다.
- 90일 기록은 감시한 날 마지막 관측값이며 종가가 확정된 매매일지가 아니다.

### 장중 앱키

현재 계좌 앱키는 공개 시세 수집과 공유하므로 기존 장중 OAuth 제한을 유지한다. 별도 `LS_GUARD_APP_KEY`, `LS_GUARD_APP_SECRET`을 비밀 바인딩으로 설정하고, 기존 `LS_ACCOUNT_APP_KEY`와 달라야 장중 감시를 허용한다. 같은 본인 국내주식 계좌에 연결한 키여야 한다. 키가 없으면 평일08:50–16:25 장중 조회를 보류하고 이유를 표시한다. 평일16:26 이후·주말에는 기존 계좌키로 수동 감시가 가능하다. 키/토큰/계좌번호를 브라우저나 공개 저장소에 저장하지 않는다.

### 배포

`Deploy private account loss guard` workflow: 테스트 → 인증 뒤 인라인 자산 빌드 → 기존 Worker 소스 지문 비교 → 기존 binding types 보존 업로드 → 인증 경계/배포 지문/비밀 이외 binding 값 불변 검증. Cloudflare Access 정책·소유자·DB·기존16:30 수집 일정은 변경하지 않는다. 이전 운영 버전 지문은 worker/account/deployed-source.sha256에 고정한다. 운영 코드가 다른 경로에서 변경되면 배포가 중지되므로 실제 변경을 검토한 뒤 지문을 갱신한다.

## 검증

`node --test tests/loss-guard*.test.mjs tests/account*.test.mjs tests/ordinary-ledger.test.mjs`

합성 데이터로 한도·반복·재무장·날짜 변경·평가손익 이관·중복 체결·조회 실패·암호화·인증 경계를 검증한다. 실계좌 손익 정합성은 본인 로그인 후 LS HTS 동일 계좌의 집계값과 대조해야 한다. 선물·옵션·해외주식·자동 주문·PC 강제 종료는 구현 범위에 포함하지 않는다.
