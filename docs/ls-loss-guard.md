# 서버 감시와 웹 푸시

2026-11-25: 계좌분석의 `백그라운드 알림 켜기`를 통해 기기별 웹 푸시를 등록한다. 브라우저의 알림 허용은 사용자 동작에서만 요청한다.

- GitHub Pages 앱 경로에 `lossguard-sw.js`를 등록한다. 이 Service Worker는 Push/알림 클릭만 처리하고 페이지 요청·캐시·계좌 데이터에 접근하지 않는다. 알림 클릭은 고정된 마켓노트 #account 탭으로 연결한다.
- 기존 계좌 Worker의 AccountPushMonitor Durable Object가 거래일 장중30초 간격으로 확인한다. 탭 이동·페이지 종료·화면 감시 중지와 별개다. 등록된 활성 기기가 없으면 알람을 중지한다.
- 주중09:00–16:15(기존 시장 예외 일정 적용)만 감시한다. 당일 검증된 LS 시장 스냅샷이 없으면 휴장 또는 개장 대기로 판단해 계좌를 조회하거나 알림을 보내지 않는다.
- 공용 LS 세션 잠금을 사용한다. 수집이 바쁘면90초 이내의 정상 계좌 관측값을 재사용할 수 있고 오래된 값으로 경고를 새로 만들지 않는다.
- 푸시는 별도 기기별 경고 상태로 한도/사전 경고/반복/재무장 여부를 판단하므로 화면 감시가 경고를 소비해도 서버 알림이 누락되지 않는다. 발송 성공 후에만 해당 상태를 진전시키고 일시 실패는 다음 주기에 재시도한다.
- 알림에는 한도 도달/사전 경고/테스트 종류만 암호화해 보낸다. 금액·계좌번호·종목은 없다. VAPID 비밀키, 등록 endpoint와 구독 키는 기존 암호화 D1에 저장하며 공개 API에 반환하지 않는다.
- 기기 관리는 무작위 capability의 해시로 검증한다. 브라우저에는 기기ID와 관리 capability만 저장한다. 해지·테스트는 해당 기기만 할 수 있다. 등록은최대8개, 테스트는분당1회이며 임의의 URL로 푸시를 보내는 요청은 거부한다.
- 전송은 MIT @block65/webcrypto-web-push v2.0.0의 RFC8291/RFC8292 구현을 번들링해 사용한다. 암호화 로직은 변경하지 않았으며 byte-array 유틸리티만 표준 Web API로 대체했다. 별도의 node:crypto 복호화/서명 검증 테스트를 포함한다.
- OS 알림 차단·네트워크·브라우저 완전 종료·절전 정책에 따라 지연 또는 수신 제한이 가능하다. iOS/iPadOS는 지원 버전의 홈 화면 웹 앱이 필요하다. 본인 기기에서 알림을 켜고 테스트 푸시 수신을 확인해야 한다.

# 마켓노트 내부 계좌분석과 손익 그래프

2026-11-25: 상단 계좌분석 메뉴를 `#account` 내부 WORKSPACE로 통합했다. 별도 페이지나 iframe으로 이동하지 않으며 기존 헤더·탭·카드·푸터 양식을 사용한다. 이전 독립 계좌 주소도 마켓노트의 #account 탭으로 이동하도록 연결한다.

- 마켓노트 내부 UI는 기존 계좌 서버에 직접 조회한다. CORS는 `https://codingzoaa.github.io`와 같은 계좌 origin에만 허용하며, 교차 출처 fetch는 credentials:omit이다. LS 키·토큰을 공개 번들/브라우저 저장소에 넣지 않는다.
- 일별 그래프는 날짜별 마지막 관측 실현손익, 누적 그래프는 유효한 날짜의 실현손익 합계다. 손실 감지기의 평가손익 포함 모드 변경과 별도로 계산한다.
- 새 기록에 realizedKRW·unrealizedKRW·guardMode를 보관한다. 이전 기록에 실현손익을 구분할 수 없으면 추정하지 않는다. 현재 일자의 정상 sample이 있으면 그 일자 실제 실현손익을 사용할 수 있다.
- 같은 날짜는 마지막 관측 1건만 사용한다. 관측 누락일을0으로 채우지 않으며, 장중 값은 잠정으로 표시한다. 최대90일 기록의 누적이지 전체 계좌 자산 증감률이 아니다.
- 막대/점을 누르거나 키보드로 선택하면 두 차트와 선택일 요약이 함께 바뀐다. 기록이 없으면 빈 상태를 표시한다.
- 탭을 떠나면 계좌 컴포넌트가 해제되고 감시 타이머·소리가 종료된다. 기존 기록 삭제·과거 원장 복원·자동 매매 기능을 추가하지 않는다.

# 기존 LS 앱키 장중 감시 · 공용 세션 조정

2026-11-25: 별도 앱키 요구는 LS의 의무 조건이 아니라 이전 구현의 보호 장치였다. 기존 앱키로 장중 감시하도록 변경한다.

- 시세 수집과 계좌 조회는 같은 앱키 지문에 해당하는 하나의 Durable Object 세션 잠금을 사용한다. 키·토큰·잔고는 조정 객체에 저장하지 않는다.
- 잠금을 얻은 작업만 TLS 연결을 열고, 그 연결에서 OAuth 발급과 모든 TR 조회를 끝낸 뒤 닫고 잠금을 반납한다. 다른 작업은 기다리거나 다음 주기에 재시도한다.
- 모든 시세 수집 진입점과 계좌 조회에 적용한다. 임의의 브라우저 요청에서 조정 객체를 직접 호출할 수 있는 공개 경로는 없다.
- 잠금은120초이고 각 LS 요청 전에 갱신한다. 만료되거나 소유권이 바뀌면 이전 연결은 더 이상 LS에 요청하지 않는다. 이전 소유자가 새 잠금을 해제할 수 없다.
- 감시는30초마다 요청한다. 시세 수집·복구 작업이 연결을 사용 중이면 실제 관측 간격은 더 길 수 있다. 소유자의 계좌 잠금과25초 재조회 제한도 유지하며 여러 탭이 중복 수집하지 않는다.
- 대기는 수집 실패로 집계하지 않고 마지막 정상 값을 유지한다.90초 이상 오래된 값은 갱신 지연 표시. 웹을 숨기거나 종료하면 감시 중지.
- Windows 독립 프로그램은 이 서버 세션 조정에 참여하지 않는다. 같은 앱키로 동시에 실행할 경우 별도 동시접속 검증이 필요하다.
- 배포는 먼저 공개 시세 서버의 세션 조정 버전을 확인하고 기존 계좌 서버에 같은 조정 객체를 연결한다. 과거 계좌 기록 삭제나 자동 수집 재활성화는 하지 않는다.

# 로그인 없는 LS 계좌분석 · 2026-11-25 변경

사용자 요청에 따라 계좌분석을 로그인 없이 공개한다. 공개 주소: https://market-note-account.kby0991.workers.dev/

- 화면에는 손실 감지기만 표시한다. 기존 거래원장·매매일지·누적 분석·보유 추정·동기화 UI를 제거했다.
- 공개 Worker는 자산과 `/api/lossguard` 및 감시 설정/조회/초기화 경로만 기존 LS 서버로 전달한다. LS 키·계좌번호·암호화 키는 공개 Worker/브라우저로 복사하지 않는다.
- 기존 서버의 `ACCOUNT_ACCESS_MODE=PUBLIC_LOSS_GUARD` 모드는 인증 없이 손실 감지기만 제공한다. 기존 계좌 원장 API는410을 반환한다. 기본 모드의 기존 인증 검증은 유지한다.
- 원장·원장 변경 이력·매매일지·인덱스·기존 동기화 상태를 운영 D1에서 삭제한다. `lossguard:` 설정·당일 기준·기록만 유지한다.
- 기존 원장/매매일지 자동 수집 플래그를 끄고 cron 목록을 비운다. 새 public 모드의 scheduled handler도 아무 작업을 하지 않는다.
- 공개 URL을 아는 사람은 계좌 손익·최초 순자산·감시 기록을 조회하고 감시 설정을 변경할 수 있다. 이는 사용자 요청에 따른 로그인 없는 공유 상태다. 주문·청산 API는 없다.
- 기존 서버의 Access 앱이나 다른 Worker 보호 정책은 변경하지 않는다. 마켓노트 메뉴는 새 공개 주소로 연결한다.
- 삭제 배포는 기존 작업의 계좌 lease가 끝난 뒤 청소 전용 lease를 얻어 수행하고 원장/변경 이력/이전 상태가0건임을 확인한다. 클라우드 제공자의 백업 보존기간을 변경하거나 영구 소거를 보장하는 작업은 아니다.

장중 별도 앱키와 LS 필드 규칙은 아래 구현 설명을 따른다. 웹은 보이는 동안만 감시하며 Windows판은 별도 기록을 사용한다.

## LS 손실 감지기 (최초 구현 설명)

첨부 KiwoomLossGuard 0.7.0 README의 공개 동작 설명을 참고해 LS용으로 새로 구현했다. 원본 exe를 패치하거나 원본 음성·이미지를 재배포하지 않는다.

## 웹

기존 본인 전용 계좌분석 Worker의 손실 감지기 패널. Access 인증을 통과한 소유자만 설정·상태·조회 API에 접근한다. 기존 암호화 D1 account_state에 일별 최초 기준·설정·최근 90일 집계 기록을 저장한다. 계좌 데이터는 localStorage/IndexedDB에 저장하지 않는다. 감시 시작을 누른 동안 30초 간격으로 조회하며 페이지 숨김·절전·종료 시 중단된다. 백그라운드 감시는 Windows판을 사용한다.

- LS t0424OutBlock.sunamt: 최초 관측 순자산, dtsunik: 실현손익, tdtsunik: 평가손익. OutBlock1.dtsunik은 종목 평가손익이므로 사용하지 않는다.
- 기본 손실 한도 최초 관측 순자산 3%, 사전 경고80%, 한도 반복5분. 고정 원화 금액 및 실현+평가 변화 모드 선택 가능.
- 평가 변화 모드: 당일 실현손익 + 현재 평가손익 − 최초 평가손익. 계좌 전체 수익률이나 현금 입출금 조정 수익률이 아니다.
- 오후 기준 기본11:00. 늦게 시작하거나 조회 지연 시 실제 관측 시각과 추정 표시. 오후 손익/수익 반납은 실현손익 차이 기준.
- CSPAQ13700 당일 주문 조회: 부분 체결과 정정은 원주문 체인 기준 1회. 원주문 누락·연속조회 미완료·필드 오류이면 횟수는 확인 불가. 주문 전송 TR은 없다.
- 3회 연속 조회 실패 경고. 누락을0으로 보정하지 않으며 마지막 정상 시각을 표시한다.
- 90일 기록은 감시한 날 마지막 관측값이며 종가가 확정된 매매일지가 아니다.

### 장중 앱키

현재 계좌 앱키는 공개 시세 수집과 공유하므로 기존 장중 OAuth 제한을 유지한다. 별도 `LS_GUARD_APP_KEY`, `LS_GUARD_APP_SECRET`을 비밀 바인딩으로 설정하고, 기존 `LS_ACCOUNT_APP_KEY`와 달라야 장중 감시를 허용한다. 같은 본인 국내주식 계좌에 연결한 키여야 한다. 키가 없으면 평일08:50–16:25 장중 조회를 보류하고 이유를 표시한다. 평일16:26 이후·주말에는 기존 계좌키로 수동 감시가 가능하다. 키/토큰/계좌번호를 브라우저나 공개 저장소에 저장하지 않는다.

### 배포

`Deploy private account loss guard` workflow: 테스트 → 인증 뒤 인라인 자산 빌드 → 기존 Worker 소스 지문 비교 → 기존 binding types 보존 업로드 → 인증 경계/배포 지문/비밀 이외 binding 값 불변 검증. Cloudflare Access 정책·소유자·DB·기존16:30 수집 일정은 변경하지 않는다. 이전 운영 버전 지문은 worker/account/deployed-source.sha256에 고정한다. 운영 코드가 다른 경로에서 변경되면 배포가 중지되므로 실제 변경을 검토한 뒤 지문을 갱신한다.
