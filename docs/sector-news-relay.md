# 정기 강세·이슈 섹터 뉴스 중계

GitHub Actions에서 공식 네이버 뉴스 검색 API로 당일 기사를 수집한다. 한국시간 날짜, 허용한 원문 언론사 도메인과 HTTPS를 검증한 최대 4개 기사를 기존 HMAC 인증 경로로 Worker에 전달한다. Worker는 서명과 본문 해시, 5분 요청 유효기간, 기사 출처·날짜를 다시 검증하고 D1의 `sector-news:naver:YYYY-MM-DD`에 저장한다. 기사·수신시각만 저장하며 인증정보는 기록하지 않는다.

## 시각과 발송 소유권

- GitHub는 한국시간 16:20부터 선 수집하고, 이후 30분 간격 발송 전후에 갱신을 시도한다. UTC cron이 실행 시각을 뜻하며 GitHub 시작 지연은 가능하다.
- Cloudflare의 기존 16:30 첫 발송, 30분 간격 재시도, 19:30 마지막 시도는 유지한다.
- GitHub 중계는 캐시만 갱신하며 텔레그램을 보내지 않는다. 실제 발송은 Cloudflare에서 처리한다.
- 성공한 `telegram:v3:YYYY-MM-DD:sector` 기록과 기존 lease를 그대로 사용해 중복 발송을 방지한다. 장 마감·수급 브리핑 기록도 변경하지 않는다.

## 실패 처리

당일 자료이고 Worker 수신 후 1시간 이내인 뉴스만 사용한다. 이전 날짜·미래 수신시각·오래된 캐시·검증되지 않은 기사는 발송에 사용하지 않는다. 중계가 없거나 오래됐으면 `NAVER_NEWS_RELAY_NOT_READY`를 기록하며 기존 재시도와 최종 실패 알림을 따른다. Cloudflare에서 네이버 API를 직접 재요청하지 않는다.

`/api/telegram-delivery-status`의 `sectorNews.mode`는 `GITHUB_RELAY`이며 `sectorNews.relay`에 ready/stale/not_received, 기사 수, 마지막 수신시각을 반환한다. API 키나 봇 토큰은 반환하지 않는다.

배포 완료 시에도 중계 워크플로우가 실행되어 연결을 검증한다. 이 실행은 기사 저장·상태 확인만 하며 추가 메시지를 보내지 않는다. 예약 실행이 19:30 이후에 시작되면 당일 정기 발송용 수집을 건너뛴다. 휴일·마감 자료 검증은 발송 시 기존 Worker 검사를 유지한다.
